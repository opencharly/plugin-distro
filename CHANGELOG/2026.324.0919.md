**`kind: source` is now served**, completing the pair `DESIGN.cue:283-284` declares: `source:` is the FIRST of the ten kinds and `os:` the second, and the contract binds them — `#SourceFields` requires `os!: #Ref @ref(os)`.

**Served beside `os` in this plugin, for the same reason `distro` and `os` share it:** a source that does not name an os cannot say what converts it into the other form (§16.4), so two homes would make two vocabularies of one concept.

```cue
#SourceAlt: {
	oci:       {oci!: #SourceImageRef, description!: …, os!: …}
	disk:      {disk!: #SourceDownload, description!: …, os!: …}   // sha256 REQUIRED
	iso:       {iso!: #SourceIso, description!: …, os!: …}         // sha256 REQUIRED
	bootstrap: {bootstrap!: #SourceBootstrap, description!: …, os!: …}
}
#SourceInput: or([#SourceAlt.oci, #SourceAlt.disk, #SourceAlt.iso, #SourceAlt.bootstrap])
```

**`D-SRC-1` is structural, not advisory — and it is PROVEN, not asserted.** `TestSourceInputAdmitsExactlyOneOrigin` runs five cases against this plugin's own compiled `#SourceInput` through **`cue.Concrete(true)`**: one origin accepted; **two origins**, **zero origins**, an **unknown key**, and an **origin missing its `os`** all rejected, each naming the requirement it enforces.

```console
{oci:"…", disk:{…}, …}   -> #SourceInput: 2 errors in empty disjunction   REJECTED (two origins)
{description:"d", os:"arch"} -> #SourceInput: incomplete value {…}         REJECTED (zero origins)
{oci:"…", description:"d", os:"arch"} -> <nil>                            accepted
```

**The `Concrete(true)` is load-bearing and is itself tested:** with plain `Validate()`, the zero-origin body **validates clean**, because `Validate` accepts an *incomplete* value. A test built on it would have asserted nothing about `D-SRC-1` and passed — **which is why the claim was unproven rather than wrong.** Removing `Concrete(true)` makes exactly the zero-origin and missing-`os` cases fail.

**The `disk`/`iso` arms carry a `#SourceDownload` whose `sha256` is required**, so an unpinned remote origin cannot be written down at all.

## Why `spec.Source` is a map, and why that is safe here

The contract's `#Source` is a union, and a union has no single Go struct — `spec.Source` is `map[string]any`, and `#SourceInput` collapses the same way.

**That is safe for THIS word and the test asserts why:** a map keeps every key, so no origin's payload can be dropped the way the `os` word's was when a narrower struct was used. **The gate `#SourceInput` is what rejects a malformed body, before the `OpLoad` arm sees it.**

### The schema half, in `source_parity_test.go`

**The first head's comment promised this file and did not have it** — the source tests were all in `invoke_load_test.go`, exercising the RUNTIME arm, and the four helper defs had no guard against spec at all. That is the same gap `#OsInput`'s inner defs had, for the same reason: the package's mirrored-defs sweep follows the `#Ds` + spec-name convention, and these carry names of their own.

| test | asserts |
|---|---|
| `TestSourceInnerDefsMatchSpec` | `#SourceDownload` / `#SourceIso` / `#SourceBootstrap` mirror spec's `#Download` / `#SourceIso` / `#SourceBootstrap` **by field** |
| `TestSourceAltHasExactlySpecsFourOrigins` | the union's arms are **enumerated from its own body** (`unionArms`) and compared against spec's four in both directions — an arm here spec lacks is a word core refuses, an arm spec has that is missing here is one an author cannot write |
| `TestSourceRequiresOsAndDescription` | **`D-SRC-2` on every arm**, read from the **comment-stripped** source so a comment quoting a field cannot satisfy it |

**`#SourceImageRef` is a scalar regex**, so it is guarded by the property that matters rather than by a field comparison: **its `sha256` digest arm must survive**, or an `oci` origin could name an unpinned remote — which `D-SRC-1` forbids for every remote origin.

**Proven red:** deleting a `sha256` from `#SourceIso` fails it.

### And the registration, which every other test bypassed

**Every test in this package calls `provider{}.Invoke(...)` directly.** So a misspelled `Word` or a wrong `InputDef` would make the kind **unreachable from a real host and ship green** — nothing would fail, because nothing asked the plugin what it serves.

**`TestNewMetaAdvertisesBothVocabularyWords` reads `Describe`** — the reply a host resolves a kind from, not the Go capability slice, because the slice is the *input* to a builder that could itself drop a row. It asserts the word → `InputDef` mapping for all three kinds, that **no unexpected kind** is advertised, and that each advertised `InputDef` is **actually defined** in the shipped schema.

**Proven red both ways:** `Word: "sorce"` reports *"does not advertise the source kind"* **and** *"advertises the unexpected kind sorce"*; a wrong `InputDef` reports the mapping mismatch.
